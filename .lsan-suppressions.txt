# LeakSanitizer suppressions for node-sqlite
#
# RULE: suppress ONLY third-party / one-time-init noise we cannot rebuild
# (V8, Node, libuv, libc, ICU, OpenSSL, build tools). NEVER suppress a frame
# that our own code allocates through.
#
# In particular, do NOT re-add `leak:napi_`, `leak:Napi::`, `leak:node_modules/`
# or `leak:napi_register_module`. Essentially every allocation this addon makes
# passes through an napi_*/Napi:: frame, so those patterns silence the addon's
# own reference/handle leaks -- the exact defect class LSan exists to find, and
# the one thing the memory CI job is here to catch.
#
# Use LSAN_OPTIONS=...:print_suppressions=1 to see which rules actually fire,
# and prune the dead ones.

# V8 internal allocations
leak:v8::internal::
leak:v8::base::
leak:v8::platform::

# Node.js internals
leak:node::
leak:node::loader::
leak:node::binding::
leak:node::options_parser::
leak:node::per_process::
leak:node::InitializeOncePerProcess
leak:node::InitializeNodeWithArgs
leak:node::CreateEnvironment
leak:node::LoadEnvironment

# NOTE: no `leak:napi_` / `leak:Napi::` here -- see the header. Those blanket
# rules masked every first-party allocation. If Node's own N-API plumbing
# proves noisy, suppress the specific node:: internal frame instead.
